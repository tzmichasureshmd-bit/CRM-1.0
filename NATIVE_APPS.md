# Tzmicha CRM — Native apps (Android + Windows)

Tzmicha CRM ships as **three surfaces that are all the same web application**:

| Surface | What it is                                          | How to produce it                    |
| ------- | --------------------------------------------------- | ------------------------------------ |
| Web     | The Next.js CRM                                     | `npm run build` + Docker (unchanged) |
| Android | Capacitor WebView loading `https://crm.tzmicha.com` | `npm run android:build`              |
| Windows | Electron app loading `https://crm.tzmicha.com`      | `npm run windows:build`              |

The native apps are **thin, secure shells around the production CRM**. They are
never separate builds: no duplicated auth, no mock APIs, no copied database.
Whatever is deployed to `https://crm.tzmicha.com` is exactly what users get in
the app — the app is just a nicer way to reach it.

Versions always follow the root `package.json` version (currently `0.8.0`):
Android reads `versionName` from `android/app/build.gradle`, Windows reads the
version from `package.json`. Bump `package.json` first, then mirror it in
`versionName` and (optionally) `versionCode` for each release.

## Header "Install App" button

A circular icon button sits right next to the Dark Mode toggle in the dashboard
header (`src/components/layout/install-app-dialog.tsx`). It opens a dialog with
two options:

- **Android App** → downloads `/downloads/Tzmicha-CRM.apk`
- **Windows App** → downloads `/downloads/Tzmicha-CRM-Setup.exe`

The visiting platform's option is shown first (Android phones and Windows PCs
see their own option first); both remain visible either way.

The dialog **never fakes the files**: on open it sends a `HEAD` request to each
download URL. If the file isn't deployed yet, the button reads _Coming soon_.
Put the real artifacts in `public/downloads/` and redeploy — the buttons light
up automatically.

The pre-existing **PWA** (Settings → _App & install_) stays fully functional and
doubles as the fallback for devices that prefer the browser.

## Android (Capacitor)

- **appId:** `com.tzmicha.crm`
- **app name:** Tzmicha CRM
- **Remote origin:** `https://crm.tzmicha.com` — set in `capacitor.config.ts`
  (`server.url`). The WebView renders the live site, so logins, Supabase
  cookies, WhatsApp, broadcasts, media and exports behave exactly as on the web.
- **Icons:** brand adaptive icon (violet background, white chat glyph) for
  API 26+ plus legacy launcher icons; generated by
  `npm run native:icons` → `android/app/src/main/res/`.
- **Splash:** dark brand-colored splash with the glyph
  (`res/drawable*/splash.png`, generated by the same script).
- **Permissions (kept minimal):** `INTERNET`, `ACCESS_NETWORK_STATE`,
  `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS` (the mic powers in-app voice notes).
  Uploads use the Android file picker and need no permission; cleartext HTTP is
  disabled everywhere.
- **Security on:** HTTPS-only, `useCleartextTraffic=false`,
  `adjustResize` keyboard handling, default Capacitor back-button behaviour
  (goes back in app history, exits at the root).

### One-time Android setup (you need Java + Android Studio once)

1. Install **Java 21 (JDK)** and **Android Studio** (bundles the Android SDK).
2. Open `android/` in Android Studio once so it downloads the Gradle wrapper
   and SDK components, or run `npx cap sync android`.
3. Create a release keystore (keep it private, do not commit):

   ```bat
   keytool -genkey -v -keystore android\tzmicha-release.keystore -alias tzmicha ^
     -keyalg RSA -keysize 2048 -validity 10000
   ```

4. Add `android/keystore.properties` (git-ignored):

   ```properties
   storeFile=tzmicha-release.keystore
   storePassword=YOUR_STORE_PW
   keyAlias=tzmicha
   keyPassword=YOUR_KEY_PW
   ```

### Build the release APK

```bat
npm run android:build
```

Output: `android/app/build/outputs/apk/release/Tzmicha-CRM.apk`

> Without a keystore the build still succeeds but falls back to the debug key
> (fine for testing, not for the Play Store).

## Windows (Electron)

- **Product name:** Tzmicha CRM · **appId:** `com.tzmicha.crm`
- **Secure shell** (`electron/main.cjs`):
  - `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`,
    `webSecurity: true`, `allowRunningInsecureContent: false`.
  - External links and `window.open()` open in the system browser, never in-app.
  - Mic for voice notes and clipboard are allowed; all other permission
    requests are denied.
  - Single-instance lock, fixed window title, `minWidth: 1024`, `minHeight: 680`.
- **Installer:** NSIS (`electron-builder.yml`) — one-click multi-user option,
  configurable install dir, desktop + start-menu shortcuts.

### Build the Windows installer (on Windows Powershell)

```powershell
npm install   # first run needs network to fetch the Electron runtime
npm run windows:build
```

Output: `dist/native/windows/Tzmicha-CRM-Setup.exe`
(plus an unpacked `Tzmicha CRM` folder and the `win-unpacked/TzmichaCRM.exe`).

## Publishing a release

1. `npm run android:build` and `npm run windows:build`.
2. Copy the artifacts into the repo so the website serves them:

   ```bat
   copy /Y android\app\build\outputs\apk\release\Tzmicha-CRM.apk public\downloads\
   copy /Y dist\native\windows\Tzmicha-CRM-Setup.exe public\downloads\
   ```

   (Both files are git-ignored — they are large binaries, but the
   `public/downloads/` folder itself is committed with a `.gitkeep`.)

3. Deploy normally. The header dialog's HEAD probes start returning 200 and the
   download buttons activate. Nothing in the CRM needs changing.

### Version bump checklist (example 0.8.0 → 0.9.0)

- `package.json` `version`
- `android/app/build.gradle` `versionName` (and `versionCode` if required)
- `NEXT_PUBLIC_APP_VERSION` in the Dockerfile build args
